# SODaVis — working notes for Claude

Sports officiating data visualizer: a browser-only React + TypeScript app (Vite, Dexie /
IndexedDB, Recharts, Tailwind) that imports game exports and reports income, time,
mileage and tax. No server; nothing leaves the user's machine.

## Read before scanning the code

1. `docs/architecture.md`: layers, state ownership, data model, extension recipes,
   traps, and the design assessment. Answers most "where" and "what does this touch"
   questions.
2. `docs/generated/module-map.md`: every module's purpose, size band (S/M/L), exports,
   imports and importers. Use it to pick the few files to open; avoid reading L files whole
   when a search will do.
3. `readme.md` (product reasoning), `toDo.md` / `projectPlan.md` (open work), `toDone.md`
   (decisions and why).

Layer rule of thumb: `model/` ← `import/` ← `db/` ← `derive/` (pure) ← `ui/store.tsx` ←
`ui/views/`. Facts (imported games) are written only by import; reference data and
annotations only by the user; everything else is derived on read and never stored.

## Commands

- `npm test`: all unit tests (Vitest). `npx tsc -b`: type check. `npm run build`.
- `npm run map`: regenerate the module map; `scripts/module-map.test.ts` fails while stale.
- `npm run dev`: the app at http://localhost:5173.
- `node test/private/e2e.mjs http://localhost:<port>`: end-to-end in Chrome against a running
  dev server; needs `data/`. It wipes that browser profile's IndexedDB, restores
  `data/reference.local.json`, and imports the real export.
- `npm run fixture` / `npm run expected`: regenerate sample / real expected figures.

## Rules

- **US English** everywhere: code, comments, UI copy, commits (color, canceled
  copy aside). Existing stored identifiers like `cancelled-nopay` stay as they are.
- **Privacy.** Real names, figures and venues live only in the private submodules `data/`
  and `test/private/`. Public code and tests use invented names; `scripts/denylist.test.ts`
  fails on a denylisted string. Never paste values from `data/` into `src/`.
- **Writes go through `db/repo.ts`.** Inline editors use the `patch*` functions (read-merge-
  write), never "save the row as rendered". A new table or field follows the recipe in
  `docs/architecture.md`; skipping a step has silently dropped data before.
- **Never hide income from Tax.** Dashboard filters (period, park, tracked sports) must not
  reach the Tax view, which uses `derived.taxResolved` / `taxTrips`.
- **Keep the docs current.** A change to layers, tables, state ownership or an extension
  recipe updates `docs/architecture.md` in the same PR; run `npm run map` when exports or
  imports change. Completed `toDo.md` items move to `toDone.md` with the reasoning.
- **Verify in the app, not just in tests,** for UI work: drive it with Playwright against a
  dev server on a spare port (5199), in light and dark, and check for console errors.

## Git and the submodules

- Three submodules: `data/` (private, real export), `test/private/` (private, real-data
  tests), `test/sample/` (public sample). A change spanning them commits the submodule
  first, then the app with the pointer (`npm run commit` does all three in order).
- **Stage files by name.** The user often has uncommitted edits of their own; `git add src/`
  has swept them into a commit before.
- Branch from `main` with `git switch -c name` (or `--no-track` when starting from a remote
  branch): `git checkout -b x origin/y` makes `y` the upstream, so a later push lands there.
- Stacked PRs target the branch below; if the lower one merges first, the upper ones merge
  into that branch, not `main`. Prefer independent branches off `main`, or land the stack
  bottom-up and retarget before merging.
- Commit messages: plain descriptive prose, no "generated by" or co-author lines.

## Windows environment

- Files are checked out CRLF (`autocrlf`); `.mjs` files are forced LF (`.gitattributes`)
  because a CRLF shebang breaks vite-node. Regexes over file text should allow `\r?\n`.
- Git Bash's `/tmp` is not visible to Windows Python; pass paths through `cygpath -m`, or
  keep scratch files in the repo root (named `.scratch-*`, deleted after use).
